# 移动端全链路适配与交互工程规格说明书 (Mobile Adaptation Master Spec)

## Problem Statement
当前系统的 C 端受试者（游客与登录用户）超过 90% 通过移动端设备（iOS Safari、微信内置 WebView、Android Chrome）访问。然而现有前端界面最初偏重桌面宽屏展示：
1. **答题核心屏交互受阻**：在 390px 视口下，点阵题干、选项矩阵与下注滑动条共用同一屏幕时，由于虚拟键盘、Safari 动态地址栏及缺乏安全区适配，导致频繁出现纵向拥挤和误触。
2. **布局横向溢出与样式变形**：落地页粘性星轨、复杂多维雷达图与部分全屏居中弹窗在 $\le 390\text{px}$ 甚至 $360\text{px}$ 宽度下出现横向滚动条，破坏原生 App 级手感。
3. **海报与分享被拦截**：原桌面端依赖 `<a>` 标签 `download` 属性触发海报下载，在移动端浏览器常被静默拦截或无法保存至相册。

## Solution
重构 C 端全量页面，确立现代移动端交互范式：
1. **抽离专属移动端答题容器**：在答题阶段抽离独立的移动端视图组件，采用「上部内容弹性滚动 + 底部常驻拇指触控操作区（Bottom Action Dock） + 滑起式提示抽屉（Bottom Sheet）」。
2. **原子化响应式重构与视口门禁**：全站 C 端引入 `100dvh`、Safe Area (`env(safe-area-inset-bottom)`) 与 $\ge 44 \times 44\text{px}$ 触控热区规范，全面消除横向溢出。
3. **原生分享与海报长按保存**：海报渲染为原生图片并优先调用系统级 Web Share API。
4. **自动化无头验收门禁**：通过 `agent-browser` 在 `390x844` 视口执行无横向溢出与触控链路断言，作为各独立 Worktree 的合并门禁。

## User Stories
1. 作为移动端游客，在 iPhone 或 Android 打开首页时，页面能够无缝贴合 `100dvh` 屏幕高度，且不会出现左右水平晃动或横向滚动条。
2. 作为移动端游客，在首屏浏览测试介绍时，能够通过单手拇指顺畅向下滚动，且粘性动效与星图动画不出现卡顿或布局重叠。
3. 作为移动端受试者，在进入测试后，顶部清晰展示进度与当前分值，题干点阵/符号矩阵自适应居中缩放，保证高清晰度且不溢出屏幕。
4. 作为移动端受试者，在答题时，选项矩阵与下注控制固定在屏幕底部拇指热区范围内，单手即可轻松点选与调整下注额度。
5. 作为移动端受试者，在遇到难题需要查看提示时，点击提示按钮能够自屏幕底部平滑滑出 Bottom Sheet 抽屉，展示消耗分值与解锁内容，且能轻松下滑关闭。
6. 作为移动端受试者，在答题过程中，所有按钮的有效触控面积均达到或超过 $44 \times 44\text{px}$，避免误触。
7. 作为移动端受试者，在 iPhone 底部黑条（Home Indicator）区域操作时，界面底部具备足够的安全内边距（Safe Area Inset），按钮不会被手势条遮挡。
8. 作为完成测试的用户，在查看认知原型（Archetype）诊断报告时，八维能力分布、优势与盲区卡片呈垂直单列流式排布，图表自适应缩放无裁切。
9. 作为完成测试的用户，在点击生成分享海报时，海报以自适应比例在屏幕居中或全屏预览，可以直接长按图片将其保存至手机系统相册。
10. 作为支持 Web Share API 的移动端用户，点击海报弹窗中的分享按钮时，能够直接调起系统级原生分享面板（微信、短信、隔空投送等）。
11. 作为移动端已登录用户，在个人中心查看认知资产库（Cognitive Assets）与历史报告时，卡片采用适合移动端的网格/瀑布流布局，支持平滑滚动与快速回溯。
12. 作为移动端用户，在点击登录/注册或用户偏好设置时，认证表单以底部抽屉（Bottom Sheet）形式展开，软键盘弹出时不遮挡输入框与提交按钮。
13. 作为移动端用户，在翻阅隐私政策与服务条款时，文字排版符合移动端行距与字号规范，返回按钮随时可见且触手可及。

## Implementation Decisions
1. **基底与容器规范**：
   - 根布局统一适配 `min-h-dvh` 与 `pb-[env(safe-area-inset-bottom)]`。
   - 全局弹窗系统引入 `BottomSheet` 统一容器，在移动端自动自底向上滑起，桌面端保持原有 Dialog 风格。
2. **核心答题屏拆端设计**：
   - 提取独立的移动端交互视图组件，将视图层与底层状态机完全分离。
   - 拆解为三个垂直分区：
     - `Header`：倒计时、题号进度、当前分数。
     - `Body (Scrollable)`：题干描述、点阵/符号矩阵、结构化代码块。
     - `Footer (Fixed Dock)`：单选题选项、置信度滑动/分级控件、提交按钮与提示抽屉唤起键。
3. **移动端海报与分享重构**：
   - 海报生成保持高精度 Canvas 渲染（2x/3x DPR），但在弹窗预览时包裹于自适应视口容器内，并输出为 `blob:` 或 `data:image/png` 的 `<img>` 标签。
   - 检测 `navigator.share` 支持情况，优先唤起原生系统分享，次选复制带 UTM 的分享短链。
4. **范围划界隔离**：
   - 管理后台（Admin）及三维天文罗盘等图表完全排除在本次改造范围外，保持原有功能与结构不受破坏。

## Testing Decisions
1. **最高层测试接缝 (Highest Testing Seam)**：
   - 采用端到端浏览器视口验收：通过 CLI 工具 `agent-browser` 驱动无头 Chromium，在真实渲染的 DOM 树上执行视口与交互验证。
2. **自动化硬性门禁指标**：
   - 视口基准：`390x844`（兼顾 `360x640`）。
   - 布局断言：`document.documentElement.scrollWidth <= window.innerWidth`（全流程页面无任何横向溢出）。
   - 交互断言：首屏按钮可点击、答题选项可点选、下注可调节、提示抽屉可正常展开与关闭、海报图片生成并挂载在 DOM。
3. **测试产物归档**：
   - 每个工单验证通过时必须截取生成对应视口下的截图快照（`mobile-preview-*.png`），存入验收记录。

## Out of Scope
- 管理后台（Admin）相关页面与数据分析视图的移动端适配。
- 后端数据模型、PRNG 阶梯算法与认知流形（Cognitive Manifold）数学逻辑变更。
- 原生 App / 混合容器（如 Capacitor / React Native）打包。

## Further Notes
- 采用 Worktree 并行模式开发，下游 4 个功能模块工单在基底工单合并前不得合入主分支。
